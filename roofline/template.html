输入区 · 推理场景配置

所有图表根据这里的参数实时计算。Prefill（预填充）处理整段提示词，是 GEMM 密集计算； Decode（解码）逐 token 生成，每步需读全部 KV 缓存，两者算力强度相差 2–3 个数量级。

算力强度 (Arithmetic Intensity, FLOP/B) = 阶段 FLOPs ÷ 阶段 DRAM 访存量。 Roofline 模型中，性能上限 = min(峰值算力, 带宽 × 强度)。GPU 的脊点 (ridge point)一般在 100–300 FLOP/B（如 H100 BF16 ≈ 295），低于脊点即访存受限。

关键假设

  • 权重读一次：每个 GEMM/GEMV pass 中权重从 DRAM 只读一次，整个 batch 共享（理想 batching）。
  • 激活读/写一次：每个阶段的输入激活读一次、输出写一次，阶段之间不重复计数。
  • MLA 近似：DeepSeek-V3/R1、GLM-4.5、Kimi-K2 的 MLA 注意力按 (nope+rope) 与 v_head_dim 维度建模，KV 缓存按压缩后 (kv_lora_rank + rope) 计。
  • MoE decode：每步激活 nactive = min(E, B×K) 个专家，激活专家的权重各读一次。
  • GPU 峰值：BF16/FP16 稠密张量核算力与 HBM 带宽（公开规格，四舍五入）。

局限性

  • 解析模型未覆盖算子融合、kernel 调度、量化 (W8A8/FP8/Int4)、P/D 分离、投机解码等系统优化。
  • 滑动窗口注意力 (Mistral/Gemma-2) 与因果掩码按简化方式处理；超长上下文 (S > 32k) 下注意力核心的强度估计偏保守。
  • 元素级/归一化阶段的 FLOPs 与访存为量级估算，非逐算子精确定义。
  • 理论 decode 上限 (tok/s) = 带宽 ÷ 每 token 流量，为理想上界，实际通常低 30–60%。
